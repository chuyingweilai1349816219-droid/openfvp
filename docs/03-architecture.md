# 引擎架构

## 模块划分

```
┌─────────────────────────────────────────────┐
│ platform（每个平台一份）                      │
│  window / input / audio-out / file / clock   │
├─────────────────────────────────────────────┤
│ gfx        渲染层：图元表、图层合成、文本排版  │
│ snd        音频：Ogg/WAV 解码、混音、通道管理  │
├─────────────────────────────────────────────┤
│ syscall    命令实现（131 条）                 │
├─────────────────────────────────────────────┤
│ vm         解释器：栈、帧、协程、全局变量      │
├─────────────────────────────────────────────┤
│ res        资源层：BIN 包、HZC1 解码、名字解析 │
└─────────────────────────────────────────────┘
```

引擎不直接调用平台 API，全部经 `platform.h` 的函数指针表，这样桌面调试和 Android 用同一份引擎代码。

## 资源名字解析

脚本里的资源名带前缀，直接对应包名：

| 脚本里的名字 | 包 | 包内条目名 |
|---|---|---|
| `graph/gaiji_ikari` | `graph.bin` | `gaiji_ikari` |
| `graph/BG026_020` | `graph_bg.bin` 或 `graph.bin` | `BG026_020` |
| `voice/01001530` | `voice.bin` | `01001530` |
| `bgm/001` | `bgm.bin` / `bgm2.bin` | `001` |
| `se/201` | `se.bin` | `201` |

**同名资源可能存在于多个包里**（例如 `graph` 前缀对应 6 个包）。解析策略：

1. 先按前缀缩小候选包集合
2. 在候选包里按名字查（每条包索引常驻内存，只查名字表，不读数据）
3. 找到就返回；同名多处时按固定优先级（`graph.bin` > `graph_bg` > `graph_bs` > `graph_vis*`）
4. 结果做缓存（名字 → (包, 索引)）

## 渲染模型

统一 **1920×1080** 画布，最终缩放到窗口。

- 画布上是若干 **primitive**，每项有 id、类型、坐标、宽高、UV、Z、alpha、旋转、缩放
- 脚本通过 `PrimSetXY/WH/UV/Z/Alpha/Draw/...` 直接改字段（字段布局见 `vm-commands.md`）
- 每帧按 Z 排序后合成
- 文本是特殊 primitive：层 0 正文、8 人名、9 章节标题，各自有独立的文本窗口状态

## 音频模型

- 通道数：BGM 1、语音 1、SE 多路
- 解码：Ogg Vorbis（stb_vorbis）+ WAV
- 混音：固定 44.1 kHz / 16 bit / 立体声
- 播放输出由平台层提供（Windows: waveOut；Android: AAudio）

## 帧循环

```
while running:
    run_vm_slice(约 1/N 秒的指令量)   // 脚本是协程驱动，不能跑死
    update_animations(dt)             // Motion* 补间
    render_frame()
    present()
    pump_input()
```

VM 不能一次跑到底：它有等待循环（等点击、等动画结束），所以按「时间片」推进，并在 `*Test` 返回「未完成」时挂起。

## 状态与存档

- 全局变量数组（≥4096 项）
- 图元表、文本窗口状态
- 存档格式 `save/sXXX.bin` 尚未解析，后续再补

## 移植优先级

1. 桌面端跑通开场（当前）
2. 渲染正确（背景 + 立绘 + 文本）
3. 音频
4. 存档
5. Android
