# 游戏内菜单（脚本侧）

> 以下内容由 DeepSeek 生成,不一定代表作者个人意愿

一句话结论：**原版的系统菜单和确认框都不是外壳画的，是脚本用图片自己画的；图片的
屏幕坐标写在 HZC1 头里，不在脚本、也不在 exe 里。** 我们外壳里 `--menu-at` 打开的
5 项文字菜单是**占位**，不参与任何像素基线。

## 0. 更正（2026-11-27）

上一轮（一百零一续）把 `menu_*_mes` 这 7 张图当成了"菜单项标签"，并据此把
`0x57300..0x57800` 那段当成"游戏内菜单"。**这是错的**：把图片打开就能看到它们是
问句 ——

* `menu_undo_mes` → 「直前の選択肢へ戻りますか？」
* `menu_exit_mes` → 「ゲームを終了しますか？」

它们是**确认框的提示图**（配 yes/no 按钮 95..98 与光标 137），不是菜单项。
真正的系统菜单在 `0x54480..0x54A00`，用 `sys_*` 素材（8 项 × 3 态）。
上一轮的冻结表（7 个动作 → 图元 94 / 开关 `global[1593..1599]` / 选项号 47..53）
**数据没错，语义标错**；本版把两块拆成 `system` 与 `dialog` 并补上几何。

## 1. 为什么可以断定它不在 exe 里

| 证据 | 内容 | 复现 |
|---|---|---|
| 命令表 | 148 条命令里带 `Menu` 的只有 `MenuMessSkip(41)` 与 `TitleMenu(141)`，没有任何"打开菜单 / 画菜单项"命令 | `ref/cmd_table.json` + `tests/verify_ingame_menu.py` |
| exe 文案 | 从 `iroseka_HD.exe` 抽出 1,506 条像样的 CP932 字符串，**没有一条**等于菜单标签（`セーブ`/`ロード`/`設定`/`終了`/`戻す`/`上書き`/`初期化`/`削除`/`メニュー`） | 同上（`jp_strings()`） |
| exe 里唯一的 `終了` | 在 `0x5cef8`，是「開くに失敗しました。終了してもよろしいですか？」的一句（其后紧跟 `して`），不是独立标签 | 同上 |

菜单文字在**图片**里，脚本只负责"载入哪张图、什么时候显示"。

## 2. 系统菜单（`0x54480..0x54A00`，入口 `0x54C68`）

8 项 × 3 态，图元号连续：`normal=141+3k`、`hover=+1`、`mask=+2`。

| # | 动作 | 素材 | 图元 | 屏幕矩形 `[x,y,w,h]` | mask 条 |
|---|---|---|---|---|---|
| 1 | save | `sys_save_1/2/M` | 141/142/143 | `[1596,229,163,60]` | `[916,251,874,43]` |
| 2 | load | `sys_load_1/2/M` | 144/145/146 | `[1371,294,173,61]` | `[675,316,874,43]` |
| 3 | hidewin | `sys_hidewin_1/2/M` | 147/148/149 | `[1218,395,165,59]` | `[517,417,874,42]` |
| 4 | undo | `sys_undo_1/2/M` | 150/151/152 | `[1079,513,190,61]` | `[402,536,874,43]` |
| 5 | config | `sys_config_1/2/M` | 153/154/155 | `[953,634,240,61]` | `[328,657,874,42]` |
| 6 | title | `sys_title_1/2/M` | 156/157/158 | `[964,755,184,59]` | `[281,776,874,43]` |
| 7 | exit | `sys_exit_1/2/M` | 159/160/161 | `[966,875,152,59]` | `[258,897,874,42]` |
| 8 | return | `sys_return_1/2/M` | 162/163/164 | `[860,995,258,60]` | `[254,1016,874,43]` |

四条硬指标（门禁逐条钉住）：

1. 8 个矩形按 y **严格递增**（229 → 995）：一条自右上到左下的弧；
2. x 从 1596（贴右边）走到 860（左下），符合"菜单挂在右侧弧线"的观感；
3. 每个 `_M` 的 874×43 横条比它那一项低 20..24 px（实测 21..23）；
4. 侧窗 `sys_window_title/right/left` 进图元 172/420/421（`0x548c7..0x54a..`）。

打开路径：脚本主循环 `0x5B57D` 判 `InputGetState(34)` bit1 或 `InputGetDown(31)` bit1，
成立则 `call 0x54C68` 再 `InputFlash(27)`；`0x54C68` 有 5 个调用点
（`0x3d21b`、`0x5b596`、`0x5b629`、`0x5b6c6`、`0x5b74c`）。这就是"右键打开菜单"的落点。

* 背景 `menu_bg` → 图元 93，`[568,440,783,200]`，中心 (959.5,540)；
* yes：`menu_yes_1`(95) `[770,535,160,50]`、`menu_yes_2`(96) `[770,525,160,71]`；

7 张提示图的**水平中心全部落在 960±3 px**（961.0 / 962.5 / 961.5 / 963.0 / 960.5 /
960.5 / 960.5），基线 y 都在 458..460 —— 说明它们是"同一块居中提示区里换图"，
不是 7 个不同位置。yes 在中心左边、no 在右边（门禁用这一点当结构断言）。

### 3.1 谁写这 7 个开关

| 写点 | 所在函数 | 写什么 | 数量 |
|---|---|---|---|
| `0x231B3..0x231CB` | `0x22F48` 初始化 | 一律 `false` | 7 |
| `0x267F7..0x2686F` | `0x25E93` 选项 setter 的 switch | 参数值（选项号 47..53） | 7 |
| `0x6CEF3..0x6CF17` | `0x6CE71` 配置块拷贝 | `global[976..982]` | 7 |
| `0x57AC0..0x57C2F` | `0x577C8` 确认框自身 | `true`/`false` 各 7 | 14 |

两条独立路径（选项 switch 与配置块拷贝）给出同一张表，才敢冻结。**注意选项号顺序
不是菜单顺序**（47 号对应第 4 个动作 qload = クイックロード），按序号猜会全错。

## 4. 几何从哪来（关键结论）

脚本里对这几个图元**没有** `PrimSetXY`：载入包装 `0x2354B` 最后调 `0x35BCC`
（`PrimSetSprt(85)`）时，x/y 两个参数传的是 `true`（= 保持不动）。真正的位置来自
**HZC1 头**：

| 偏移 | 字段 |
|---|---|
| `0x14` | width |
| `0x16` | height |
| `0x18` | **x position in game screen** |
| `0x1A` | **y position in game screen** |

坐标是 **1920×1080 实机像素**（不是图元的 1024×640 虚拟画布）：`sys_save_1` 的
x=1596 已经超过 1024。所以"菜单几何"不需要版面表、也不需要拟合 —— 读头就行。
`scripts/scan-ingame-menu.py` 用 `extract/graph/`（`bin_archiver` 解包产物）读这 4 个
字段，只输出数字，不含像素；解包目录不存在时几何一栏留空，门禁自动跳过那几条。

### 4.1 直观旁证（不是运行截图）

把原素材按头部坐标拼到 1920×1080 上（`work/compose_menu_preview.py`，只读 `extract/`）：

* `out/c/menu-system-layout.png`：8 项正好嵌在左右两个表盘窗口之间的空隙里，
  SAVE → LOAD → HIDE → UNDO → OPTION → TITLE → EXIT → RETURN 自上而下排成弧；
* `out/c/menu-dialog-layout.png`：六边形面板 + 「直前の選択肢へ戻りますか？」+
  「はい」「いいえ」，正好落在面板的提示行与按钮行上。

这两张是"原图 + 头部坐标"的静态拼合，用来肉眼核对冻结的几何，**不是**运行截图，
也不进仓库（`out/` 已忽略）。它能说明的是：头部坐标确实就是游戏里用的坐标 —— 否则
8 个词条不可能刚好落进两侧表盘的空当。

### 4.2 同一套坐标把整个游戏内 UI 都覆盖了

`0x2354B` 这个载入包装被脚本用了 98 次，分布如下（`ref/ingame-menu.json` 的
`inventory`，逐条含图元号、载入偏移、头部矩形）：

| 家族 | 条数 | 是什么 | 几何特征 |
|---|---|---|---|
| `sys_` | 44 | 系统菜单 8×3 态 + 侧窗 3 件 + 抓屏帧 17 张 | 环形弧 + 表盘窗口；`sys_cap_*` 是**运行时生成**的抓屏，没有素材、没有头部矩形 |
| `fc_` | 37 | 阅读时的快捷命令条：11 个命令 × 常态/高亮 + 4 个额外状态 + 11 条帮助条 | 按钮全 **40×40**，两排**交错**：y=1010 / 1035，x 从 1560 到 1810；11 条帮助条全在 `(1600,975,210,30)` |
| `menu_` | 14 | 确认框：7 张提示图 + yes/no 4 张 + 背景 + 光标 + `menu_byebye` | 全部以 960 为中心 |
| `slf_` | 3 | 存读档界面背景与零件：`slf_load_bg` / `slf_save_bg`（全屏 1920×1080）、`slf_prt_sheet`（1640×1010） | 走 `PrimSetGraph` 直连（图元 2500/2501），**不**经 `graph/` 包装 |

11 个命令键分别是：`back`、`qload`、`qsave`、`play`、`skip`、`voice`、`system`、
`wincls`、`save`、`load`、`lock`（`lock` 独有 4 个状态）。

这条清单的价值：**游戏内 UI 的位置全部来自素材头**，没有一条需要版面表。谁再想"按
截图量出来的坐标写死一张表"，先看一眼这里 —— 表本来就不该存在。

同样的静态拼合也验证了命令条：`out/c/menu-fcbar-layout.png` 里 11 个 40×40 图标
两排交错挤在右下角，帮助条（如「記録の保存」）正好压在图标群上方 —— 与冻结的
`(1600,975,210,30)` 完全吻合。

## 5. 我们外壳里的现状（占位，不是原版）

`bin/fvp.exe --menu-at N` 打开的是 `src/gamemenu.c` 里的 5 项文字菜单
（`SAVE/LOAD/OPTION/TITLE/QUIT`，`y=300`、行距 64、宽 320）。这些数字是自己定的，
原版没有对应常量。保留理由：脚本菜单还进不去时，至少能验输入通路
（`tests/verify_gamemenu.py`、`tests/verify_menu_actions.py`）。

打开时会多打一行日志，避免误认：

```
menu: NOTE placeholder overlay, original menu is script-side (see ref/ingame-menu.json)
```

## 6. 门禁与工具

```powershell
# 静态扫描（HCB + HZC1 头；不需要跑游戏）
python scripts/scan-ingame-menu.py --json ref/ingame-menu.json

# 门禁：结构自洽 + 几何断言 + 命令表证据 + exe 文案证据 + 重扫比对

```

`tests/verify_ingame_menu.py` 共 **84 项**断言，六组：

1. **系统菜单**：8 项 / 动作顺序 / 图元连续 / 素材命名 / 8 个矩形在屏内 /
   y 严格递增 / 弧线两端范围 / mask 条低 20..24 px 且宽 874 / 侧窗 3 件 / 5 个打开点；
2. **确认框**：7 提示 / 图元 94 / 只有 exit 挂 796 / 开关 1593..1599 / 7 张图 /
   中心 960±12 / 基线 458..460 / yes 在左 no 在右 / 背景中心 / 光标；
3. **开关**：选项号 47..53、配置默认 976..982、运行时 1593..1599 三条链同序；
   35 个写点按"函数 + 写入值"分类齐全；每个动作至少 1 个触发点；
4. **UI 清单**：98 个载入点 / 四家族计数 44·37·14·3 / 每个都绑图元 /
   除 `sys_cap_*` 外都有头部矩形 / 矩形都在 1920×1080 内 / 命令条 26 键 + 11 帮助条 /
   键全 40×40 / 两排交错 y=1010·1035 / 帮助条同一矩形 / `lock` 4 态 /
   `slf_*` 全屏且不经 `graph/` 包装；
5. **命令表 / exe 文案**：148 条里只有 `MenuMessSkip(41)`、`TitleMenu(141)`；
   exe 没有独立 CP932 菜单标签，`終了` 只以对话句出现；
6. **重扫比对**：有 HCB 时逐字段重算（无 `extract/` 时几何跳过，不谎报通过）。
